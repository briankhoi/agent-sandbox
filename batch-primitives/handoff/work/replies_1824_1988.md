## #1824, thread on `sandbox_client.py:576` (exit releases an attached batch)

Approved option (fix lands in #1988):
> Agreed. `get_batch` takes over the Lease instead of reading it, so a tool that only inspects ends up owning the batch. #1988 now changes exit cleanup in both clients so it releases only batches the client claimed and detaches the ones it attached through `get_batch`, with `detach()`'s default grace. `delete_all()` keeps releasing every tracked batch, since that's an explicit call. ## #1824, thread on `sandbox_batch.py:880` (retry moves the shared pacing cursor)

> Both, split by cause. A response with a Retry-After still moves the shared cursor. APF computes that value per priority level, which all of a batch's creates share, so every worker waiting is what the apiserver asks for. Every other retry (a transport error, or a 5xx or 429 without Retry-After) now waits its own backoff and then takes the next normal slot, so one blip no longer delays the other workers. A retry still always takes a pacing slot, which matches how client-go sleeps a retry's own backoff and then goes through its shared rate limiter. The change is in #1988, and `acquire()` in #1991 checks its deadline again after the backoff, since other creates keep taking slots meanwhile.

## #1988, CodeRabbit `ConnectTimeoutError` thread

## #1988, CodeRabbit outside-diff note "keep batches eligible for release after close()"

> This is intended. `close()` only shuts the client down, and its docstring says it stops batch Lease renewal without releasing anything. It treats sandboxes the same way. A sandbox whose connection it closes leaves the registry, so atexit won't delete it either. To delete batches, use `async with`, `delete_all()` or `batch.release()` before `close()`. A batch left behind still ends at its claims' `shutdownTime`.

## #1988, CodeRabbit outside-diff note "wake `_changed` waiters in `_stop_batches()`"

> Fixed. `_stop_batches()` now marks each handle detached and calls `batch._changed.notify_all()` under the handle's lock before it stops the background tasks. The detached flag came from #1986 and the notify from 9c73ac3d in this PR. A consumer waiting in `events()` or `group_outcomes()` wakes, sees the handle is detached, and raises `BatchError`.

## #1988 PR body ("What this PR does" section, replaces the `iter_ready_groups()` text)

> This PR is the thirteenth in a series that adds batches to the Python SDK. Today a claimed batch only exposes `members()`, so a caller has to poll to find Ready members and can't tell which groups have reached quorum. This PR adds two consumers that wait on the batch state instead.
>
> - `group_outcomes()` yields one `GroupOutcome` per group as soon as its outcome is known. A group that reaches `min_ready` yields its first `min_ready` Ready members in the order they became Ready. A group that can't reach it still yields, with `error` set to `QuorumUnreachableError`, or to `BatchTimeoutError` if `quorum_timeout` passes after the last create's pacing slot.
> - `events()` yields a `BatchEvent` once per initial claim as it becomes Ready, fails, or is lost. Called after `group_outcomes()`, it yields a group's members only after that group has yielded successfully, so a failed group hands out none. Calling `group_outcomes()` after `events()` raises, because the first consumer fixes how members are handed out.
> - `BatchState` does the fill accounting at each claim transition in O(1), so both consumers scale to tens of thousands of claims. A re-attached handle reads the quorum timeout from its Lease annotation and counts it from attach.
> - The `claim_batch` e2e test now waits through `group_outcomes()`, and the README, the docstrings and the generated SDK reference describe both consumers.

> - Its first three commits follow up on review comments from #1824. Client exit cleanup detaches a batch attached with `get_batch` instead of deleting it, and still releases batches the client claimed. A create retry after a transport error waits its own backoff instead of delaying every other create, while a Retry-After still slows the whole batch. Batch Lease requests also retry a refused or timed-out connect.
